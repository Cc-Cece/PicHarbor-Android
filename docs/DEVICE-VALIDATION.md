# 真机验收记录要求

## 环境

记录测试日期、设备型号、Android 与 WebView 版本、是否未 Root、APK SHA-256、gpmc 基线。账号仅使用自有测试账号；对外记录用代号，勿提供密码、Cookie、Token 或 adb 私有目录转储。

## 顺序

1. 清洁状态启动，测试取消登录；重新登录并完成两步验证。记录是否有浏览器拒绝、设备验证或加密令牌错误。
2. 成功后重启应用，检查凭据复用。保留首次令牌到期时间，等待真实到期，再检查续期并上传新文件。不能通过人为修改缓存到期时间代替。
3. 使用从未上传过的新 JPEG、HEIC、MP4，分别记录原始哈希、大小、来源。不要使用已经存在的同内容文件；实例会排除已存在条目。
4. 上传时保持前台。官方相册定位条目，核对备份质量和空间占用；处理完成后复查。用人工检查记录对应 UI 勾选。
5. 从官方渠道下载原始文件，选择该下载文件做 SHA-256 比较。另检查 EXIF、拍摄时间、视频音轨；不能用本地源文件完成回下载验收。
6. 测试断网、凭据撤销和退出账号。确认错误明确，不出现已验证免配额的虚假结果；确认退出删除本地凭据及登录数据，云端文件保留。
7. 导出报告，附上不含敏感信息的官方条目观察记录。报告本身不自动宣告整体通过。

## 阻塞后的开发诊断

只适用于 debug APK；先安装并启动一次，然后退出。将自有有效凭据放在项目之外的本机私密文件中：

```powershell
python tools/inject_diagnostic.py C:/private/my-auth.txt
```

多个 adb 设备时加 `--serial DEVICE_SERIAL`。工具通过 stdin 传入，不把凭据放在命令行。APK 启动后一次性读取并删除注入文件，再通过 Keystore 加密存储。不要把该文件提交或放入报告。

这种路径仅验证引擎与上传；报告为 `diagnostic_only`，不能视为自助登录成功。release 构建不读取注入文件，应用没有对外导出的凭据注入组件。

## 结果分类

每项记录通过、失败、未证实或阻塞。只有完整样本、登录、重启复用和真实续期均有证据，才审核整体通过。免配额结论限定在测试样本和时间，不代表永久账号权益。
